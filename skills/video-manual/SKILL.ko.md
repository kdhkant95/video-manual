# 영상 매뉴얼 (video-manual) — 한국어판

> 이 문서는 [SKILL.md](SKILL.md)의 한국어 번역본으로, 사람이 읽기 위한 것입니다. AI가 실제로 읽고 따르는 원본은 `SKILL.md`이며, 두 문서의 내용이 다르면 `SKILL.md`가 기준입니다. 스킬 동작을 바꾸려면 `SKILL.md`를 고친 뒤 이 문서를 맞춰 주세요.

## 이 스킬은 언제 쓰이나요

소프트웨어 제품의 스크린샷, Figma 링크, 또는 실행 중인 서비스의 URL로 애니메이션 영상 매뉴얼(사용법·튜토리얼·온보딩·기능 소개 영상)을 만듭니다.

프로덕트 프로젝트(브랜드, 대상 연령·도메인·B2C/B2B에서 나오는 UX 라이팅 문체와 모션, 배경 템플릿, 로고) → 씬 → 스토리보드 초안 → 영상의 네 단계로 진행합니다. 로컬 스튜디오 웹 화면에서 사용자가 문구와 순서를 고치고 프레임마다 코멘트를 남겨 AI에게 수정을 요청할 수 있고, 대화만으로도 진행할 수 있습니다. 결과물은 MP4입니다.

"영상 매뉴얼", "사용법 영상", "튜토리얼 영상", "기능 소개 영상", "가이드 영상"을 만들어 달라는 요청이나 "스튜디오 요청 처리해 줘"에 쓰입니다. 화면이나 Figma 링크만 주면서 이 기능을 사용자에게 어떻게 설명할지 묻는 경우에도 쓰입니다.

## 개요

제품 화면을 자막이 달린 짧은 따라 하기 영상으로 바꿉니다. 애니메이션 커서가 화면을 클릭하며 넘어가고, 하이라이트와 확대가 시선을 이끌고, 애니메이션 텍스트가 각 단계를 설명합니다.

작업은 네 단계입니다. 결정은 사용자가 하고, 제작은 AI가 합니다.

| 단계 | 사용자 | AI |
| --- | --- | --- |
| 1. 프로덕트 프로젝트 | 제품이 누구를 위한 것인지 밝히고, 브랜드 색·배경 템플릿·로고·브랜드 가이드를 정한다 | 문체 규칙을 만들고 모션을 조정한다 |
| 2. 씬 | 스크린샷이나 Figma 링크를 첨부한다 | Figma 프레임을 가져온다 |
| 3. 스토리보드 초안 | 키 화면, 순서, 문구를 확정한다 | 사용자가 고칠 초안을 쓴다 |
| 4. 영상 | 영상을 보고, 문구와 순서를 고치고, 프레임에 코멘트를 남긴다 | 동작을 넣고, 모든 프레임을 검수하고, 코멘트를 반영하고, 렌더링한다 |

사용자가 가장 신경 쓰는 것은 문구와 순서입니다. 그래서 제작에 들어가기 전인 3단계에서 확정하고, 4단계에서도 MP4를 렌더링하기 전까지는 계속 고칠 수 있습니다.

사용자와는 사용자의 언어로 대화합니다. 자막은 따로 요청이 없으면 제품 UI의 언어로 씁니다.

## 두 가지 작업 방식

**스튜디오 사용(기본).** 로컬 웹 화면에 네 단계가 나옵니다. 사용자는 거기서 작업하고, ✦ 표시가 있는 버튼을 누르면 요청이 쌓입니다. AI가 그 요청을 가져가 처리하고 답합니다. 시작하기 전에 [references/studio.md](references/studio.md)를 읽습니다. 그 문서가 이 주고받기의 규약입니다.

**대화만으로.** 사용자가 브라우저를 열고 싶지 않거나 로컬 서버를 띄울 수 없을 때는, 같은 네 단계를 대화에서 묻고 보여 주며 진행합니다. 아래 "스튜디오 없이"를 참고합니다.

어느 쪽이든 만들어지는 파일은 같으므로, 한 프로젝트를 두 방식 사이에서 오갈 수 있습니다.

## 프로젝트 구조

모든 파일을 사용자 프로젝트의 `video-manual/` 아래에 둡니다. 그래야 그 제품의 모든 매뉴얼이 프로파일 하나를 함께 씁니다.

```
video-manual/
├── product-profile.json     # 제품당 하나: 대상, 문체, 모션, 배경
├── brand/                   # guide.md (붙여 넣은 브랜드 가이드), 로고
├── requests.json            # 스튜디오에서 쌓인 요청
└── <매뉴얼-이름>/            # 영상 하나당 폴더 하나 (예: create-task/)
    ├── screens/             # 01-board.png, 02-new-task.png, ...
    ├── storyboard.json      # 처음에는 초안, 이후 완성된 스토리보드
    ├── comments.json        # 스튜디오에서 남긴 프레임 코멘트
    └── out/                 # manual.html, manual.mp4, stills/, frames/
```

## 준비

스크립트는 이 스킬의 `scripts/` 폴더에 있습니다. 렌더링에 필요한 의존성은 처음 한 번만 설치합니다.

```bash
cd <스킬-폴더>/scripts && npm install
```

그다음 스튜디오를 백그라운드로 띄우고 사용자에게 주소를 알려 줍니다.

```bash
node <스킬-폴더>/scripts/studio.mjs video-manual --open
```

다음에 무슨 일이 일어나는지 한 문장으로 알립니다. 사용자가 1단계를 채우면, ✦ 버튼으로 보낸 것은 AI가 가져가 처리합니다. 그런 다음 [references/studio.md](references/studio.md)에 적힌 대로 요청을 기다립니다. 스튜디오는 AI가 기다리는 동안에만 "AI 연결됨"으로 표시하므로, 사용자가 스튜디오에서 작업하는 동안에는 그 대기 루프에 머뭅니다.

## 1단계 — 프로덕트 프로젝트

`video-manual/product-profile.json`에 이미 `voice` 블록이 있으면 제품 설정이 끝난 것이므로 그대로 씁니다. 영상마다 따로 다듬는 것보다 한 제품의 영상들이 일관된 것이 더 중요합니다.

없으면 사용자가 양식(이름, 도메인, B2C/B2B, 대상 연령, 기기, 강조색, 배경 템플릿, 선택 사항인 로고와 브랜드 가이드)을 채우고 `profile` 요청을 보냅니다. 그러면:

1. `product` 블록과 `brand/guide.md`를 읽습니다.
2. `voice` 블록을 씁니다. 말투, 문장 끝맺음, 자막 최대 길이, 쓰지 않을 말, 제품 용어가 들어갑니다. [references/voice-guide.md](references/voice-guide.md)를 읽습니다. 사용자의 브랜드 가이드가 그 문서의 일반 조언보다 우선합니다.
3. 같은 대상에 맞춰 모션을 조정합니다. [references/motion-profiles.md](references/motion-profiles.md)를 읽습니다. 프리셋과 배경은 사용자가 골랐으므로, AI는 대상에 따라 속도·크기·이징을 조정합니다.
4. 한두 문장의 `rationale`(이유)을 덧붙입니다.

대상 연령, 도메인, B2C/B2B 이 세 가지가 모든 자막을 결정합니다. 양식에 빈 항목이 있거나 화면과 맞지 않으면, 문체 규칙을 쓰기 전에 먼저 묻습니다.

## 2단계 — 씬

서로 다른 화면 상태마다 이미지 한 장씩을 `screens/`에 두고, 등장 순서대로 번호를 붙입니다. 눈에 보이게 바뀌는 상태(모달이 열림, 드롭다운이 펼쳐짐, 양식이 채워짐)는 각각 이미지가 필요합니다. 영상은 클릭의 결과를 다음 스크린샷으로 넘어가는 것으로 보여 주기 때문입니다.

보통은 사용자가 스튜디오에서 올리거나 Figma 프레임 링크를 적습니다. 프레임마다 링크 하나씩, 영상에 나오는 순서대로 적고, 각 링크가 화면 전체인지 앞 화면 위에 뜨는 것인지 표시합니다. Figma 링크가 담긴 요청(`scenes`, 또는 `figmaFrames`나 `figmaUrl`이 있는 `draft`)이 오면 [references/studio.md](references/studio.md)에 적힌 대로 처리합니다. 프레임을 PNG로 내보내고 `coordWidth`에 쓸 논리 너비를 기록하며, 앞 화면 위에 뜨는 프레임은 그 화면 위에 올려 한 장으로 만듭니다. 레이어 메타데이터도 읽습니다. 요소의 정확한 위치를 주므로 픽셀을 보고 추정하는 것보다 훨씬 믿을 만합니다. 프레임 링크는 요청할 가치가 있습니다. 페이지 전체 링크만 받으면 쓸 화면을 AI가 직접 찾아야 하고, 큰 디자인 파일에서는 그 비용이 영상의 나머지 전부보다 큽니다. Figma 접근은 AI가 실행되고 있는 클라이언트의 Figma 연결과 사용자 본인의 계정으로 이루어집니다. 연결이 없으면 그렇다고 말하고 내보낸 PNG를 요청합니다.

따라 하기에 필요한 상태가 빠져 있으면 그 단계를 건너뛰지 말고, 어떤 화면이 없는지 말하고 요청합니다. 보는 사람이 따라갈 수 없는 건너뜀은 매뉴얼의 목적을 무너뜨립니다.

## 3단계 — 스토리보드 초안

`draft` 요청은 2단계나 3단계에서 보낼 수 있고, 링크가 담겨 있으면 Figma 가져오기까지 포함합니다. 요청이 오면 모든 화면과 프로파일을 읽고 `storyboard.json`에 초안을 씁니다. 장면을 순서대로 놓고, 각 장면에 `caption`(자막)과 그 화면에서 일어나는 일을 적은 `note`(연출 메모)를 답니다. 동작은 아직 넣지 않습니다. 영상의 범위를 정하고 문구를 쓰는 방법은 [references/manual-script.md](references/manual-script.md)를 읽고, 모든 문장을 프로파일의 문체로 씁니다.

사용자는 스튜디오에서 초안을 고치다가 문구와 순서가 맞으면 "영상 만들기 요청"을 누릅니다. 그 `produce` 요청이 곧 승인입니다. 그 전에는 동작을 넣지 않습니다.

## 4단계 — 영상

### 제작

[references/storyboard-schema.md](references/storyboard-schema.md)를 읽고, 승인된 초안을 완성된 스토리보드로 바꿉니다. 각 장면의 `note`를 따라 동작을 넣고 `coordWidth`를 지정합니다. 자막은 승인된 그대로 둡니다.

좌표가 가장 틀리기 쉬운 부분입니다. 정확한 값이 있으면(Figma 메타데이터, DOM 좌표) 그것을 씁니다. 이미지뿐이라면 자세히 들여다보고 추정합니다. 여기서 틀린 것을 잡아내는 것이 아래 확인 절차의 역할입니다.

### 사용자가 보기 전에 확인

빌드한 뒤 검수용 프레임을 뽑습니다. 클릭, 텍스트, 자막 교체가 일어나는 순간마다, 그리고 각 장면의 끝에서 한 장씩 나옵니다.

```bash
node <스킬-폴더>/scripts/build.mjs video-manual/<이름>/storyboard.json
node <스킬-폴더>/scripts/render.mjs video-manual/<이름>/out/manual.html --stills video-manual/<이름>/out/stills
```

`build.mjs`는 스토리보드를 검증하고, 모든 자막을 프로파일의 문체 규칙에 비추어 검사하고, 장면별 시간을 출력합니다. 오류는 고칩니다. 사용자가 직접 쓴 문구에서 문체 경고가 나오면 문구는 그대로 두고 답변에서 그 경고를 알립니다.

프레임을 읽고 하나씩 확인합니다.

- 커서 끝이 자막에서 말하는 요소 위에 있는가?
- 하이라이트 테두리가 요소 전체를, 그리고 그 요소만 감싸는가?
- 확대한 뒤 대상이 화면 안에 온전히 들어오고 읽을 수 있는가?
- 입력된 글자가 입력 칸 안에 있고 안내 문구(placeholder)를 가리는가?
- 자막이 모두 보이고 두 줄을 넘지 않는가?
- 말풍선이 요소나 커서를 가리지 않고 맞는 요소를 가리키는가?

모든 프레임이 통과할 때까지 스토리보드를 고치고, 다시 빌드하고, 프레임을 다시 뽑은 뒤 요청에 답합니다. 커서가 버튼 옆을 클릭하면 매뉴얼 전체가 틀려 보이므로, 그런 것을 사용자가 먼저 발견하게 해서는 안 됩니다.

### 검수 루프

스튜디오 4단계에서 사용자는 다음을 할 수 있습니다.

- 자막·제목·화면 텍스트를 고치고 장면 순서를 바꿉니다. `storyboard.json`에 바로 저장되며 요청은 생기지 않습니다.
- 프레임에서 멈추고, 위치를 찍고, 코멘트를 쓴 다음 코멘트들을 `revise` 요청으로 보냅니다.

`revise`는 [references/studio.md](references/studio.md)에 적힌 대로 처리합니다. 코멘트가 달린 프레임을 뽑아 사용자가 본 것을 그대로 보고, 코멘트가 말하는 것만 고치고, 새로 뽑은 프레임으로 고쳐졌는지 확인하고, 코멘트마다 답합니다. 사용자가 순서를 바꾼 뒤에는 각 클릭이 여전히 그다음 화면으로 이어지는지 확인합니다. 연결이 끊어졌다면 조용히 고치지 말고 사용자에게 알립니다.

사용자가 만족할 때까지 이 루프를 반복합니다.

### 렌더링

사용자는 스튜디오의 버튼 하나로 MP4를 내보냅니다. AI가 직접 렌더링하려면:

```bash
node <스킬-폴더>/scripts/render.mjs video-manual/<이름>/out/manual.html --out video-manual/<이름>/out/manual.mp4
```

렌더링에는 대략 영상 길이만큼, 느린 컴퓨터에서는 두세 배의 시간이 걸립니다. 1분이 넘는 매뉴얼은 백그라운드로 실행합니다. 결과 파일의 경로, 길이, 용량을 알립니다.

## 스튜디오 없이

같은 네 단계를 대화에서 진행합니다.

1. **프로젝트** — 화면과 UI 문구에서 대상 연령·도메인·B2C/B2B를 추론하고, 그렇게 읽은 것이 맞는지 질문 하나로 확인받습니다. 그다음 프리셋·강조색·배경을 포함한 프로파일 전체를 AI가 씁니다.
2. **씬** — 사용자가 준 이미지를 `screens/`에 복사하거나, 브라우저·Figma 도구가 있으면 직접 캡처합니다. 페이지 전체를 가리키는 Figma 링크 하나만 받았다면, 한눈에 읽을 만큼 작은 페이지가 아닌 한 탐색하기 전에 쓸 프레임의 링크를 순서대로 달라고 요청합니다.
3. **초안** — 스토리보드 초안을 쓰고 표(단계, 화면, 연출, 자막, 화면 텍스트)로 예상 길이와 함께 보여 준 뒤 승인을 기다립니다. 처음부터 끝까지 진행하라고 했다면 그대로 진행하고 초안의 위치를 알립니다.
4. **영상** — 위와 같이 제작하고 확인한 뒤 `out/manual.html`의 위치를 알립니다. 이 단독 페이지는 영상을 재생하고 문구·순서를 고치는 패널을 갖고 있으며, "수정본 내려받기"로 `storyboard.edited.json`을 받아 돌려줄 수 있습니다. 돌려받으면 무엇이 바뀌었는지 정리해 의도대로 읽었는지 확인받고, `storyboard.json`으로 저장하고, 다시 빌드해 프레임을 확인합니다. 그다음 렌더링합니다.

## 이후 변경

- **문구나 순서**: 사용자가 스튜디오에서 고치거나 AI에게 말합니다.
- **문체**("너무 딱딱해요", "우리 사용자는 그보다 나이가 많아요"): 프로파일의 `voice` 블록을 바꾼 뒤 자막을 그에 맞게 다시 씁니다.
- **느낌**("너무 느려요", "너무 통통 튀어요"): 개별 장면이 아니라 프로파일의 모션 값을 바꿉니다. [references/motion-profiles.md](references/motion-profiles.md)의 조정 표를 참고합니다.
- **한 단계가 이상해 보일 때**: 그 장면의 동작을 고치고 해당 프레임을 다시 확인합니다.

무엇을 바꾸든 다시 렌더링하기 전에 다시 빌드하고 프레임을 확인합니다.

## 제약

요청이 아래 제약에 걸리면 분명하게 알립니다.

- 화면은 정지 이미지입니다. 스크롤, 마우스를 올렸을 때의 상태, 앱 내부 애니메이션은 재현하지 않습니다. 상태별 스크린샷으로 보여 줍니다.
- 음성 해설과 배경 음악은 없습니다. 설명은 자막과 화면 텍스트가 담당합니다.
- 스튜디오에서는 문구와 장면 순서를 고칩니다. 어디를 클릭하고 무엇을 강조할지는 AI에게 코멘트로 요청해 바꿉니다.
- 출력은 기본 16:9입니다. 다른 비율은 스토리보드의 `meta.width`와 `meta.height`로 정합니다.

## 문제 해결

- **`playwright-core is not installed`**: scripts 폴더에서 `npm install`을 실행합니다.
- **`no browser found`**: Google Chrome을 설치하거나, scripts 폴더에서 `npx playwright install chromium`을 실행합니다.
- **`ffmpeg not found`**: ffmpeg를 설치하거나 `FFMPEG_PATH`를 지정합니다. 보통은 `npm install`이 `ffmpeg-static`으로 함께 설치합니다.
- **스튜디오에서 요청이 "대기"에 머물 때**: `studio.mjs wait`를 실행 중인 에이전트가 없는 것입니다. 실행하거나 `studio.mjs pending`으로 확인합니다.
- **4단계에 영상 대신 오류가 나올 때**: 어떤 장면이 없는 이미지를 가리키거나 좌표가 화면 밖에 있습니다. `build.mjs`가 해당 장면을 알려 줍니다.
- **글꼴이 이상해 보일 때**: 영상은 컴퓨터에 설치된 글꼴을 씁니다. 프로파일의 `font.family`를 설치된 글꼴로 지정합니다.
